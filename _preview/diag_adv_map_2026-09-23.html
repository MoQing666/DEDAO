结论

旧问题已闭环：游戏无 bug。卡住是探针缺了三处覆盖层处理，导致越过未关闭的界面去点了旧渲染的高亮节点。
引擎层 200 局 / 10200 步 / 200 次抵达 Boss，0 失败；UI 层对账零「此路不通」、DOM 高亮与引擎 advNextChoices 始终一致。

一、卡住的真实机理（时序错位）

iter4 · 移动前 —— 一致 ✓
引擎当前 c0_0
引擎应高亮 ["c1_0"]
DOM 实际高亮 ["c1_0"]
点击 c1_0 → 移动成功 c0_0 → c1_0
iter5 · 移动后 —— 旧地图（覆盖层还开着）
引擎当前 c1_0（已前进）
引擎应高亮 ["c2_0","c2_1"]
DOM 实际高亮 ["c1_0"]（陈旧）
点击 c1_0 → 此路不通

advMove 成功后地图不会立即重渲染：须先开中间界面（章节 / 弹层 / 战斗），关闭后走 advAdvanceToMap() 才 renderAdvMap()。这些中间界面都是全屏遮罩， 玩家根本点不到下面的旧地图 —— 所以真实游玩不会遇到。设计如此，非缺陷。

二、探针缺的三处覆盖层处理（已修）

  1. 章节选项在 #chapter-choices —— #chapter-actions 本身是一个 <button> 而非容器；带选项的章节（残魂传承 / 秘地探查 / 体力不支）会把「继续」display:none。只点「继续」＝ 永远点不掉。
  2. 静室 / 坊市 / 秘藏走 #modal，不是章节遮罩 → 必须单独处理。且绝不能点含「撤离 / 撤退 / 收手」的按钮（会直接结束秘境）；全是撤离类时只点 #modal-close。
  3. 战斗按钮是 #b-atk / #b-spell / #b-guard / #b-flee，位于 .battle-btns；不存在 #battle-actions（原先按容器找按钮，取到空数组 → 死循环）。

三、决定性验证：hook 引擎真函数做对账

Engine 是顶层 const（IIFE），不挂 window → 用 win.eval('Engine') 取； 改方法属性即可拦截（ui.js 闭包引用同一对象）。每次点击前用 UI 那份存档现算 advNextChoices 与 DOM 高亮比对。
