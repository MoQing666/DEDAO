一、检测结论（只读对账，可复跑）

检测 ① 命格 · 战斗相关效果 → 基本已实装，仅 1 处死配置

❌ 唯一问题： 厚土之体（houtu，绿阶 · type:'attr'）带 effect:{ defMul: 0.05 }， 但读取它的 getDestinyAttrMult()（engine.js:914）写了 dest.type === 'combat' 才认 —— 所以「防御 +5%」在命格面板 / 图鉴里会给玩家看到，实战里永不生效。

这与 2026-09-18 修掉的那批 tribBonus（天命之子 / 天道宠儿，同为 attr 类）是同一类 bug。
修法三选一：① 去掉 engine.js:914 的 type 限制（推荐，与 tribBonus 同手法，一次修完所有 attr 类武器字段）； ② 把厚土之体 type 改成 'combat'；③ 把 defMul 换成六维 attr:{ti:2} 之外再加 def 加成。
脚本：node _probe/audit_destiny_combat.js（新增，只读）。

检测 ② 功法（102 门）是否实装 → 效果全实装，但文案缺 3 处

逐字段对账 TECHNIQUES（心法 37 / 法术 50 / 遁术 15）：

  • 心法 12 个附加效果全部有 getter 且全部被调用：mult、hpMax(固定气血)、hpMul、mpMul、atkMul、defMul、critPct、atkSpd、spellMul、craftTimeReduce、guard、thorns —— 无死效果。
  • 法术（dmg/cost/buff/debuff/stun/dotBurn/dotPoison/disaster/heal/mpRestore/lifesteal/element）全部走唯一结算入口 applySpellEffects()，含 buff 的 *Dur 单独持续回合 —— 无死效果。
  • 遁术flee / guard 生效（guard 走与心法同一条减伤通道）。

三、待你拍板的 3 件事

  • 决策 1厚土之体的 defMul 死配置要不要顺手修？　推荐改 engine.js:914（去掉 type==='combat' 限制），一次修完所有 attr 类的武器字段。这是引擎改动，会进 46 个命格的结算路径 —— 需要跑全量 358 用例验证。
  • 决策 2遗忘要不要「返还资源」或加冷却（如每世 3 次）？　默认方案：无返还、无次数限制（遗忘只是清理已学的低阶功法，让功法页干净）。若你想要限制，我加一个 s.forgetLeft。
  • 决策 3静室是「加高弹窗」还是「改成独立整页」？　默认方案是加高（min-height:46dvh），改动小、不影响秘境返回路径。
